# 0068 focus prompt and audience compatibility

Additive only. No existing row's meaning changes and nothing is backfilled.

## `lesson_configurations.focus_prompt`

- New nullable `text` column. Every pre-existing row reads back `null`, which
  means "no focus": objectives, outline, narration and storyboard generation
  behave exactly as before, and their params omit `focusPrompt` so the params
  hash is unchanged.
- A check constraint mirrors `lessonFocusPromptSchema` (`@avlp/schemas`): the
  value is `null` or 1-1,000 characters with no surrounding spaces. The API
  validates first; the constraint is the backstop.
- User content, treated like source text: it is never logged and never copied
  into audit metadata.

## `learning_objective_sets.focus_coverage`

- New nullable `jsonb` column holding `objectiveFocusCoverageSchema`, written
  only by `objectives/v3` jobs. Sets generated by `objectives/v2` (including v2
  jobs still in flight when this deploys) keep `null`, which the API reads as
  "no coverage report".

## Audience values

- `lesson_configurations.age_band` and `difficulty` are unconstrained `text`
  columns validated at the API boundary, so the new values
  (`adult-intermediate`, `adult-professional`, `advanced`) need no DDL.
  Existing values are unchanged.

## `usage_operation_type` += `ai.lesson-intent`

- `ALTER TYPE ... ADD VALUE IF NOT EXISTS` is idempotent. `model_calls.operation_type`
  is plain `text` and needs no change.

## Deployment order

- Apply before API and pipeline-worker instances that read or write the new
  columns or record `ai.lesson-intent` usage.
