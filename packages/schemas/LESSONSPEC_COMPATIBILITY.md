# LessonSpec compatibility

`LessonSpec` version `1.9` is the current immutable, strict contract. Consumers must parse unknown JSON with `parseLessonSpec` before use.

Version `1.9` (ST-104, ADR-013) only widens `audience`: `ageBand` adds `adult-intermediate` and `adult-professional`, and `difficulty` adds `advanced`. A `1.8` document is read **in place**, not migrated. It parses to exactly the stored JSON, so its content hash and render identity do not change. It remains restricted to the `1.8` audience values, and a `1.8` document carrying a new value is rejected. Writers emit `1.9`, and saved lesson versions record which one they hold. `readableLessonSpecVersions` lists both.

`parseLessonSpec` explicitly migrates compatible `1.0` through `1.7` documents to the current version. Version `1.2` scalar IPO values are transformed losslessly into one-item input and output collections. Version `1.3` comparison labels become left and right structured subjects without losing text. Version `1.4` cause/effect labels become ordered node IDs and explicit directed connections without losing text. Version `1.5` labelled-diagram descriptions become the approved shapes-only fallback and bounded semantic anchors. Version `1.6` analogies require a teacher-led migration because their former free-text mappings cannot be converted safely into explicit concept-to-familiar-system pairs. Version `1.7` summary strings upgrade to structured takeaway items when concise; overlong summaries require a teacher-led migration. A legacy definition, process, cause/effect graph, analogy, diagram, or summary that exceeds current density limits is rejected for a teacher-led migration; content is never silently truncated. Unknown versions are rejected. Additive or breaking future changes require a new schema version, migration fixtures, and explicit compatibility handling; no consumer may infer compatibility from an unknown version.
